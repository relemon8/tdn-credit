# Development log

## Design baseline

Rust local server + browser, Pure Rust core, 24 monthly periods plus a turn-0
allocation. Initial NAV/cash JPY 10 billion, no holdings. 10 fictional issuers,
20 fixed-rate bonds. MIT. No monetization, telemetry, paid APIs, accounts or
runtime LLM calls. Platform order: Linux, OpenBSD, macOS, Android, Windows.

Key reconciliations: issuer events trigger a final reprice before trading;
internal credit and published ratings are distinct; clean/accrued/dirty prices
are explicit; annual PD is converted to monthly; rates/spread attribution uses
the same DCF as portfolio/index pricing. Realized/unrealized is a separate
accounting view, not another additive return source.

## Phase 1 — Simulation core

- Implemented workspace, financial newtypes, domain-separated ChaCha8 streams,
  10 issuers/20 bonds, curve interpolation, semiannual DCF, numerical durations,
  issuer cashflow/funding model, credit score/fair spread/market spread,
  rating evidence lag, dynamic PD, recovery and liquidity.
- Headless 24-period simulation runs. No OS, UI, network or storage dependency
  in `credit-core`. Currency amounts in issuer statements are explicitly oku
  (JPY 100 million); portfolio settlement amounts are integer JPY.
- Snapshot, portfolio/index and attribution scaffolding was introduced here
  to preserve the inputs later phases need; no UI is required by this API.
- Breaking change: none (new repository).

## Phase 2 — Financial tests

- Eleven initial tests including property tests passed on macOS arm64.
- Verified units, cash/trade invariants, invalid-order atomicity, DCF response,
  credit direction, rating lag, independent RNG, save replay, benchmark parity,
  and residual reconciliation across 32 randomly chosen 24-month paths.
- Seed 1919 headless run completed, residual zero in every period.
- Linux verification is still required; macOS checks do not satisfy the Linux
  completion gate.

## Phase 3 — Basic local UI (initial checkpoint)

- Leptos SSR with native HTML forms and Axum, original terminal-style CSS,
  responsive layout, five navigation pages, disclosure-aware issuer detail.
- Chose server-rendered interactions initially: no Node, JS or WASM build is
  needed. This is a change from planned hydration, with the same Rust UI
  component model; hydration can be added when interaction latency warrants it.
- Storage/platform scaffolding added for local server lifecycle. Save and
  trading UI are exercised and hardened in their corresponding phases.

## Phases 3–4 — Browser UI and trading

- Workspace build/tests passed; all five pages returned HTTP 200. Verified Ask
  purchase, cash/holdings, SQLite autosave and JSON export over loopback HTTP.
- Firefox headless rendered desktop 1440px and mobile 390px. Mobile page had no
  document-level horizontal overflow. No runtime JS, CDN or external assets.
- Orders include session token and revision; stale forms are rejected. UI uses
  current bid/ask with explicitly labeled face amounts. No short selling.
- Remaining: browser testing of the final feature set and packaging.
- Breaking changes: internal pre-release save fields were expanded; no public
  save compatibility is promised before the first release.

## Phases 5–6 — Events and optional memes

- Added 50 unique typed event definitions (10 macro, 10 sector, 30 issuer),
  conditions/cooldowns, and applied-event before/after records. Defaults are
  generated by payment failure or PD, never by a random headline.
- TNOK acquisition uses new debt equal to 40% of prior debt, target EBITDA at
  12x acquisition price, and near-term integration expense. Test verifies
  leverage approximately 3.8x → 5.7x. It caught an excessive integration-cost
  coefficient; corrected the coefficient before continuing.
- Published rating migration generates news; generic market commentary remains
  separate from factual issuer news.
- Presentation reads immutable financial state. Meme RNG domain, contexts,
  rarity, global cooldown and per-phrase cooldown are independent of finance.
- Calibrated sector score offsets and spread adjustments so initial relative
  value differences are plausible; healthy issuers no longer all hit the fair
  spread floor. These are fictional peer calibrations, documented model data.
- Remaining: broaden save/meme/attribution tests and final browser replay.

## Phases 7–8 — Attribution, analysis, benchmark and scoring

- Implemented exact DCF counterfactual waterfall, bond-level attribution,
  carry/coupon cashflows, rates, spread, default/recovery, costs and residual.
- Index uses the same prices/cashflows/default settlement as the portfolio;
  initial fixed units and cash retention are explicit (no index turnover costs).
- Added six DCF stress scenarios, liquidation costs, issuer/sector/rating/tenor
  exposures, NAV chart, monthly history, composite score and final rank.
- Implemented drawdown, annualized sample Sharpe, best/worst month, average
  duration/rating, default losses and trading costs. Zero variance is not an
  infinite Sharpe. Highest rank requires positive excess and diversification.
- Refined maturity-bucket aging and credit-line drawdown: actual unpaid amounts
  trigger default rather than allowing unlimited automatic borrowing.
- Remaining: multi-platform builds, packaging, license audit and final QA.

## Phase 9 — Local persistence and Linux packaging

- Versioned JSON state in SQLite repository, atomic transactions, autosave per
  successful operation, manual slot, export and CLI import with backup slot.
- Save validation rejects incompatible versions, invalid references/balances,

  silently overwriting the player's session.
- XDG/macOS/Windows path handling and portable ./data mode; assets embedded.
- MIT license, README, dependency notices and cargo-deny license check pass.
- Linux x86_64 static binary executed under QEMU Linux: initial 24 finance/save/
  meme tests, headless 24 turns, HTTP 24-turn trading and restart/load passed.
- Linux aarch64 static binary executed under QEMU/HVF without an external NIC:
  tests, headless, full local HTTP play and restart/load passed.
- Breaking changes: prototype save structs changed during unreleased development;
  released engine/data/schema compatibility is checked explicitly.

## Phase 14 — Polish and robustness

- MARKET remains three focused issuer cards. Global directory is a sortable,
  searchable dense table; selected issuers expose two tradable bond cards.
- Added keyboard focus/skip link, NEXT MONTH access key, mobile layout, financial
  terms, disclosure-aware history, exposure details, charts and scenario notes.
- Critical held-issuer news is never dropped merely to meet the three-item limit.
- Default claim UI suppresses meaningless live yield/fair spread and shows fixed
  recovery. Published badges explicitly mean issuer ratings.
- Extended property checks to all difficulties and debt/maturity conservation.
- Tested negative EBITDA events so buybacks/dividends cannot increase cash and

- Final release regression checks: 31 tests; property paths cover 32 generated

  The 390px mobile layout was verified with an actual 390px iframe viewport,
  avoiding Firefox macOS headless minimum-window-size ambiguity.

## Final financing-model review

- Found that mean-reverting every issuer's interest expense toward a common
  funding rate understated persistent HY debt costs. Replaced it with legacy
  fixed-debt costs, 20% floating-rate policy sensitivity, actual rolled debt
  repricing at Treasury + issuer market spread, and priced credit-line drawings.
- Moved macro events before issuer operating/funding updates so a policy action
  affects the month's funding conditions in the intended order.
- Added two directional/exact funding-cost tests; all 30 tests and Clippy pass
  locally, including the 160 all-difficulty property paths. Rebuilt/rechecked
  release binaries after this change; no stale earlier artifact is shipped.

- Baseline PD multiplier correlations were tempered (exponent 0.35) after a
  near-par expected-loss sanity check exposed double counting. Added the initial
  credit-premium/loss-budget test: 31 tests now pass locally.
- Breaking change: data version is now 2. The financing/PD model change is not
  silently applied to prototype data-v1 saves; compatibility validation rejects
  those saves. Engine/package version remains the first unreleased 0.1.0 MVP.

## Continuous play after evaluation

- 24/36か月は成績評価の目安に変更。翌月進行・売買・保存を停止せず、到達済みの既存セーブも継続できる。
- 成績とチャートを経過月数に対応。24か月時点の案内は残し、以後は運用分析で累積評価。継続中にモデル内部の真値を開示してしまう旧終了後パネルは撤去。
- 満期は契約どおり償還。健全企業の同じ返済順位の新債を別IDで作成（短期側3年、長期側7年、現行曲線とSpreadからCoupon）。企業の借り換え財務モデルと二重に負債を加算しない。
- プレイヤーの償還金は現金で返し、再投資は任意。比較指数は同一企業の新債へ元本だけMidで再投資し、利息/Default回収金は現金で保持。
- 償還済み契約・履歴を保持し、通常一覧では非表示、チェックで参照可能。破綻企業は復活させない。
- テスト: 120か月の継続・決定論・Save JSON復元・P/L照合、新旧債の区別・償還額・新債の取引、40→60か月のSQLite復元、UI継続ボタンと情報非開示。
- 互換性: 既存データを読み込める。Rust APIのis_overは評価到達を表すevaluation_completeへ改名。旧版バイナリは24か月超のSaveに対応しないため継続後は更新版で読む。
- 残る制約: 企業は既存10社。全社が破綻した場合に新企業や無根拠な再生は生成しない。月数の上限はu32とローカルの記憶容量に制約される。CLIサンプルは評価月で止める。
- 長期運用で表面化する境界条件も修正: 元の満期日を過ぎたDefault請求権を早期に消さず、回収金の支払いまで保持。回収前に消失せず二重損失も出ないテストを追加。
- 検証結果: 全40テスト、Clippy warnings deny、format、release build成功。HTTPで24→25か月進行、売買、24か月セーブからの再開、40か月までの新債発生、40か月セーブ・復元を確認。ホームの実行ファイルを更新。
